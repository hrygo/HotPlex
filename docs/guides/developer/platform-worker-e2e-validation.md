# 三端与四 Worker 端到端验收

验收目标是公共能力行为一致、原生差异明确反馈。一次成功聊天不能证明该组合的权限交互、停止、恢复和故障处理均可用。

## 证据等级

- **Source**：代码阅读、调用链及能力声明。记录 Git commit 和文件。
- **Test**：真实 HotPlex 组件配合本地平台 API / Worker 协议替身；浏览器测试使用真实浏览器及模拟 WebSocket。可进入普通 CI。
- **Live**：真实平台账号与真实 Worker 的独立测试会话。记录 Worker 版本、ACP agent 身份与版本、服务端 commit、配置模式、时间及脱敏证据。

缺少 Live 时填 `NOT_RUN` 或 `BLOCKED`，不得用单元测试、12 组合名字或截图加载成功代替 Live。权限、模型和原生命令依赖实际 Worker 版本及 agent 协商结果。

## 自动验证

在仓库根目录执行：

```bash
make test-contract-matrix
go test ./internal/worker/... ./internal/gateway/... ./internal/messaging/... -count=1 -race -shuffle=on
pnpm --dir webchat test
pnpm --dir webchat exec tsc --noEmit
pnpm --dir webchat test:e2e:matrix
pnpm --dir webchat exec playwright test e2e/terminal-interactions.spec.ts --project=chromium
```

契约矩阵包含固定的 12 组合 × 8 核心场景：接受与 ACK、去重冲突、投递失败、停止、下一轮、重置重连、终态发送失败、增量背压。交互和原生能力还有各包专项测试，不应把这 96 项称作全部功能覆盖。

浏览器测试通过 `PLAYWRIGHT_PORT` 使用独立端口；如默认 Playwright 浏览器缺失，可按 `webchat/playwright.config.ts` 使用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向已安装的兼容浏览器。记录此环境差异，不降低断言。

终态交互专项覆盖四 Worker 的 done、SESSION_TERMINATED、terminated/deleted 状态，检查未完成卡片过期、已完成结果保留和迟到回执不回写。该专项与停止后下一轮输入的核心矩阵一起运行。

## Live 前提

在专用测试频道、群聊或 WebChat 工作区逐项操作。只使用无敏感内容的临时项目与测试附件。发送消息、变更测试 Bot 配置、重启服务须由操作者确认目标与范围；普通自动测试不需要真实平台凭据。

每个组合先记录实际 Worker 类型，不能仅靠客户端菜单显示判断。ACP 还需记录 agent 宣告的 loadSession、prompt 模态和原生命令。测试权限模式应允许出现审批请求，否则记录该项 `BLOCKED`，不能把自动批准算作审批卡片通过。

## 每个组合的功能清单

| 功能 | 操作 | 通过标准 |
| --- | --- | --- |
| 身份与路由 | 在两个独立测试会话中发送不同标记 | Worker、工作目录和会话归属正确，无跨会话串流 |
| 普通输入 | 发送短文本与长输出请求 | ACK / 接受反馈、文本流和单一终态一致；可继续发送 |
| 工具 | 请求读取临时项目内一个测试文件 | 工具开始、结果与最终回复可见；不泄漏其他会话内容 |
| 停止 | 长输出过程中连续点停止两次 | 中止当前轮，保留会话，无重复 terminal / crash fallback |
| 下一轮 | 停止后立即发送新标记 | 正常完成，无旧光标、旧错误或旧增量污染 |
| 补充 | 当前轮执行中补充文本 | 原生注入或明确排队；不静默丢失、不重复投递 |
| 权限 | 分别允许、拒绝、超时一次 | Worker 收到对应结果；卡片状态与实际接受结果一致 |
| 问答 | 单选、多选、自由文本及多问题 | 答案不被压扁、截断或错序；不支持时明确反馈 |
| 表单 | 触发有必填和类型约束的 elicitation | 合法数据送达，非法数据可修正，取消可结束等待 |
| 命令与模型 | 查询命令目录，执行支持与不支持的命令 | 不把控制命令误作普通 prompt；不支持时明确拒绝 |
| 图片与文件 | 发送小测试图片及普通文件 | Worker 实际看到内容或明确告知不支持/下载失败；文件名占位不算通过 |
| 语音 | 配置允许时发送测试语音 | 转写或文件降级可见；STT/TTS 未配置单独标注，不视为 Worker 缺陷 |
| 重连与恢复 | 关闭客户端再打开同一会话；在测试环境模拟 Worker 恢复 | 历史可读；区分原生恢复、文本历史回填和新会话 |
| 重置 | 执行 /reset 后发送新消息 | 旧 forwarder 不污染新上下文，旧输入不自动重投 |
| 失败与重试 | 测试环境注入平台投递失败/Worker 不可用 | 错误可见、状态收敛；未知投递结果不自动重放 |

模型选择、权限模式调整、原生命令目录和文件读取能力不强制使用相同的原生机制。降级必须描述实际结果，例如“恢复了文本历史，未恢复原生工具状态”。

## 当前明确的能力差异

以下是 HotPlex adapter 的实现边界；实际 Worker 版本和 ACP agent 的协商结果仍须在 Live 中记录。

| Worker | 会话内明确不支持的固定命令 | 恢复边界 |
| --- | --- | --- |
| Claude Code | `/clear`；需要全新上下文时使用 `/reset` | 原生会话文件存在时恢复；文件不可用可能新建 |
| Codex | `/model`、`/perm` | 新线程回填有界文本历史，不等同原生工具状态恢复 |
| OpenCode | 仍由实际服务端决定可用模型等动态能力 | 复用远端 session；确认不存在后新建并提示历史未恢复 |
| ACP | `/compact`、`/rewind`、`/mcp` | 依 agent 的 loadSession；不可用时回填现有文本历史并提示 |

上表中明确不支持的固定命令在目录中隐藏，但保留名称占用；同名技能不能把这些控制命令变成普通输入。ACP 问答与表单适配仅适用于发出已知扩展方法的 agent，不能据此宣称所有 ACP agent 都支持这些能力。

Slack 的文本审批和表单动作需要明确请求 ID，ID 保持大小写；未知或过期 ID 不会回退到其他请求。多个待处理请求应使用对应卡片。自由文本问答保留完整回答，多问题中的未答项保持原题位置。

WebChat 当前没有附件上传入口，只提供已声明的文本/代码输入。Slack 和飞书的媒体通过平台下载、可选转写及本地文件路径进入 Worker。附件、语音和 TTS 应分别验收，不将 Worker 的 image 能力声明当作三端上传闭环已经完成。

## 记录模板与结论

复制 [十二组合证据模板](../../assets/e2e/platform-worker-matrix-template.md)，为同一候选 commit 建立记录。每个单元格应链接具体操作或测试结果，`PASS`、`FAIL`、`BLOCKED`、`NOT_RUN` 分开统计。保留功能级失败，不能用一个组合的普通聊天成功覆盖其他失败。

证据只保留合成测试标记、受控错误分类、必要版本信息和脱敏截图。不要收集 prompt 原文、访问令牌、cookie、真实用户标识或完整环境变量。清理由测试资源创建者执行，核对归属后删除专用测试会话与临时附件。
